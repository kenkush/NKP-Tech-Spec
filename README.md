#### Раздел 1 Общие требования
Внимание! Весь проект разделён на два этапа. Не все разделы и пункты техзадания всего проекта входят в первый этап. На этом этапе должны решиться только те вопросы, которые указаны в этом техзадании для первого этапа. 
- 1.1.	Система не приводит к автоматической отставке государственных служащих (информационный режим).
- 1.2. Система не требует обращения в ЦОН или иные государственные инстанции.
- 1.3. Код системы публикуется на GitHub (открытая лицензия).
- 1.4. Система не собирает и не хранит паспортные данные, ФИО, адреса проживания, почтовых адресов. Для системы достаточно от каждого заявителя смартфона и второго проверочного телефона без интернета,  на котором будут активированы математические часы. Дата регистрации, фото паспорта нужны исключительно для этапа регистрации. Доверенные лица обязаны иметь открытую регистрацию.
- 1.5. Система не имеет центрального сервера — вся информация хранится на устройствах пользователей и в распределённых хранилищах (GitHub, Google Диск).
- 1.6	 Система фиксирует момент начала голосования и далее ведёт отсчёт времени локально. При подключении к сети производится корректировка времени по узлам синхронизации. Это внутренний таймер.
- 1.7 Фиксация времени действия: Для каждого голоса сохраняется неизменяемая временная метка момента его регистрации. Временная метка (Timestamp): Для каждого голоса в базе данных будет создана запись, которую невозможно отредактировать задним числом.
#### 2.	Регистрация и идентификация пользователя
- 2.1. Первый запуск (анонимный бланк)
При первом запуске приложение генерирует хешированный анонимный бланк — уникальный идентификатор, который не связан с телефоном, email или IP-адресом. Бланк используется только для привязки дальнейших шагов регистрации к одному сеансу.
- 2.2. Фиксация номера телефона (защита от ботов)
- Для предотвращения массовой автоматической регистрации система фиксирует два номера телефона заявителя: а) первый_ основной, на котором установлено приложение и б) второй_ проверочный, без интернет связи( кнопочный или сенсорный _ на выбор), на котором будут установлены математические часы.
- После фиксации система выдерживает паузу 24 часа (разрыв временной корреляции).
- По истечении 24 часов (в любое время в течение следующих 30 дней) при открытии приложения заявителю выдаётся хешированный бланк регистрации.
- Если регистрация не начата в течение 30 дней, заявка аннулируется, номер телефона удаляется.
- Телефонные номера используются только для защиты от ботов и не связываются с голосованием, псевдонимом или пинкодом.
#### 2.3. Генерация секретного ключа TOTP
Приложение НКП на основном телефоне генерирует уникальный секретный ключ по стандарту RFC 6238 (алгоритм SHA-1) для TOTP-аутентификации.
- 2.4. Передача секретного ключа на второй телефон
Секретный ключ передаётся на второй телефон (без доступа к интернету) по защищённому Bluetooth-соединению.
Приложение на втором телефоне (в режиме «Токен») принимает ключ и сохраняет его в зашифрованном виде.
Резервный способ: ручной ввод ключа пользователем (если Bluetooth недоступен).
- 2.5. Второй телефон как TOTP-генератор
Второй телефон обязательно должен быть зарегистрирован на территории КР (косвенное подтверждение гражданства).
Он используется как аппаратный генератор TOTP-кодов (8 цифр, смена каждые 60 секунд).
На втором телефоне установлено то же приложение НКП в режиме «Токен» (без доступа к интернету, только генерация кодов).
- 2.5.1 Принцип конфиденциальности: Телефонные номера используются исключительно как барьер против ботов на этапе входа. Они хранятся в изолированном зашифрованном контуре и технически не могут быть связаны с результатами голосования, псевдонимом или ПИН-кодом пользователя.
- 2.6. Ввод первого и второго кода с часов
Пользователь вводит в приложение на основном телефоне первый 8-значный код с часов (проверка, что часы настроены правильно).
Система ждёт смены кода (60 секунд) и запрашивает второй 8-значный код (новый).
#### 2.7. Пинкод для голосования
- Второй введённый код становится постоянным пинкодом пользователя — его электронной подписью для всех голосований, оценок, жалоб и предложений.
- 2.8. Присвоение псевдонима
- Пользователь придумывает уникальный псевдоним (обязательно).
- Формат: первая буква — заглавная латиница с точкой (например, G. Gvozdika, J. Jizel). Остальная часть — любой язык (русский, английский).
- Псевдоним не привязывается к реальному имени. Без псевдонима регистрация невозможна.
- 2.9. Бумажная копия пинкода и псевдонима (физическое подтверждение)
#### 2.9. Физическое и юридическое подтверждение (Сбор данных внутренней камерой) 
- Приложение показывает созданный пинкод (8 цифр), псевдоним на экране, дату регистрации и требует, чтобы пользователь записал их от руки на бумагу. Для защиты от внешнего вмешательства, ботов и иностранцев система требует последовательно зафиксировать через внутреннюю камеру приложения:
- 1.	Листок бумаги с написанным от руки псевдонимом, пинкодом, текущей датой и личной ручной подписью.
- 2.	Оригинал паспорта (ID-карту) гражданина КР с обеих сторон.
#### 2.10. Одновременная токенизация и полная очистка памяти (Главный узел анонимности) 
- Программа внутри смартфона мгновенно считывает полученные снимки и генерирует единый анонимный Токен (цифровой жетон), в который зашифрованы и данные паспорта, и данные бумажной копии. Этот токен намертво привязывается к ПИН-коду (подписи) и Псевдониму пользователя.
•	В распределенную P2P-сеть уходит только математическая метка (хэш паспорта), чтобы этот же человек не мог зарегистрироваться второй раз.
•	Только после успешной генерации токена приложение выдает уведомление: «Ваши паспортные данные и бумажная копия безвозвратно удалены из системы. Псевдоним успешно привязан к ПИН-коду подписи».
•	Все исходные фотографии (и паспорта, и бумаги) физически и безвозвратно уничтожаются в памяти смартфона в эту же секунду.
#### 2.10.1. Хранение пинкода (хеш + соль) 
- Приложение хранит только хеш пинкода + соль (необратимое математическое преобразование). Сам пинкод (8 цифр) в чистом виде не хранится нигде. «При каждом голосовании пинкод подписи активирует токен».
- Без загрузки фото и паспорта регистрация не завершается.
- Фото и паспорт не передаются на сервер (сервера нет) и не хранятся в приложении. Они используется только для одноразовой проверки пинкода,  псевдонима, гражданства и даты регистрации. 
- Бумажная копия (физический листок с пинкодом, псевдонимом и датой регистрации, записанными от руки) остаётся у пользователя и является единственным способом восстановления доступа в систему.

2.12. Анонимный режим (по умолчанию)
Псевдоним обязателен, отображается в таблицах голосований.
Права: оценка госслужащих (тайно), выдвижение проектов (анонимно), жалобы. Рейтинг участника не вычисляется.
#### 2.13. Открытый (верифицированный) режим (добровольно)
- Пользователь подаёт добровольное заявление и предоставляет: паспорт, ИНН, email, телефон, адрес.
- После проверки получает статус «Верифицированный участник», ФИО публикуется в профиле. Псевдоним не используется.
- Отдельный пинкод для открытого аккаунта (не связан с анонимным).
- Права: открытое выдвижение проектов, открытое обсуждение, открытое голосование (голос привязан к ФИО), а также возможность тайного голосования (с отдельным пинкодом, имя не раскрывается).
#### 2.14. Две таблицы результатов голосования
- По каждому голосованию система формирует две независимые таблицы:
- Анонимные результаты — все голоса, поданные тайно (с псевдонимами).
- Открытые результаты — только голоса, поданные открыто (с ФИО верифицированных участников).
#### 2.16. Перерегистрация на другой второй телефон
- Если пользователь приобрёл другой второй телефон (без интернета), он может выполнить перерегистрацию: вводит коды с нового телефона, второй введённый код становится новым пинкодом, старый пинкод теряет силу.
- Пользователь может менять пинкод в любое время через повторную перерегистрацию.

#### Регистрация для граждан КР за рубежом
- Для  граждан  КР  за  рубежом  —  отдельная  процедура  регистрации
- 2.19. Регистрация граждан КР за рубежом (через родственников)
- 2.19.1. Кто может приглашать
- Только зарегистрированный пользователь в КР, который является кровным родственником приглашаемого: родители, дети, сёстры, братья (по заявлению под личную ответственность). Степень родства не проверяется системой автоматически, но в случае злоупотребления аккаунт приглашающего блокируется.
- 2.19.2. Данные, предоставляемые зарубежным гражданином
- ФИО (как в свидетельстве о рождении).
- Зарубежный телефонный номер.
- Скан/фото свидетельства о рождении (или паспорта гражданина КР, если есть).
#### 2.19.3. Процесс регистрации
- Инициация заявки
- Родственник в КР подаёт предварительную заявку, указывая ФИО и зарубежный телефон приглашаемого.
- Подтверждение «живого» пользователя (код с часов)
- Система запрашивает у приглашающего ввести текущий код с его математических часов. После успешного ввода генерируется секретный TOTP-ключ и ссылка-приглашение.
- Передача ссылки
- Приглашающий отправляет ссылку родственнику за рубежом (мессенджер, email).
- Завершение регистрации гражданином за рубежом
- Пользователь за рубежом переходит по ссылке, устанавливает приложение и загружает скан/фото свидетельства о рождении (или паспорта КР).
- Система проверяет документ автоматически (по шаблону). После проверки оригинал документа удаляется, остаётся только хеш (цифровой отпечаток) и дата верификации.
- Затем пользователь настраивает TOTP-генератор (второй телефон), вводит первый и второй код, получает пинкод и псевдоним (по общим правилам).
- Защита от дублей
- Если ФИО + зарубежный номер уже существуют в базе, регистрация блокируется («Этот гражданин уже зарегистрирован»).
- 2.19.4. Ограничения на Этапе 1
Один аккаунт в КР может пригласить не более 10 родственников (лимит может быть изменён НКП).
При аномальной активности (много приглашений за короткое время) заявки временно блокируются до ручной проверки.
- 2.19.5. Ответственность за достоверность
Приглашающий родственник несёт ответственность за то, что приглашённый действительно является гражданином КР. В случае доказанного нарушения (поддельное свидетельство, заведомо ложные данные) его аккаунт блокируется, а право приглашать аннулируется.
- 2.19.6. Отображение в системеПользователи КР за рубежом отображаются в таблицах с  меткой «КР-зарубежье». Все правила голосования, проектов, жалоб для них не меняются.

2.2 Анонимность голосования
Система не связывает пинкод с конкретным голосом в открытом виде. Даже при физическом доступе к телефону невозможно определить, как проголосовал пользователь.
 #### 3. Бланки голосования и оценок   
3.1. Выдача стартовых бланков (7 штук)
После завершения регистрации пользователь получает 7 виртуальных бланков. Каждый бланк содержит уникальный номер и поле для подписи-пинкода.
3.2. Получение дополнительных бланков (без ограничений)
Пользователь может запросить любое количество дополнительных бланков. Система добавляет их мгновенно, бесплатно, без согласования.
3.3. Статус использованных бланков (не удаляются)
После использования бланк становится недействительным для нового голосования, но не удаляется. Он сохраняется в архиве как доказательство голосования (уникальный номер, пинкод в виде хеша, временная метка).
#### 3.4.  «Виды бланков» 
- Form №1 – Голосование по статьям легитимности власти

#### Единое правило подсчёта голосов для всех бланков
- На всех бланках голосования по любому вопросу фиксация ответов происходит по единому правилу:
- По каждому пункту голосования гражданин выбирает один из трёх вариантов (например: «Да», «Нет», «Воздержался»).
- Каждый участник в соответствующей ячейке (на пересечении строки и столбца) ставит единицу (1) в том варианте, который он выбирает.
- Единица — это числовой маркер, который участвует в математических операциях.
- Галочка (✓) не используется, так как она не поддаётся прямому суммированию.
- При подведении итогов система автоматически суммирует все единицы по каждой строке (пункту голосования) и по каждому варианту («Да», «Нет», «Воздержался»).
- Доля каждого варианта вычисляется по формуле:
- Доля варианта = (Количество единиц по варианту / Общее количество единиц по строке) × 100%
- Общее количество единиц по строке = сумма голосов «Да» + «Нет» + «Воздержался» по данному пункту.
- Результат округляется до одного десятичного знака (например, 45.6%).
- Сумма долей по трём вариантам всегда равна 100%.
- Формула универсальна и не зависит от названий вариантов ответа («Да/Нет/Воздержался», «Подтверждаю/Не подтверждаю/Воздержался», «Одобряю/Не одобряю/Воздержался» и т.д.).
- Количество подтверждённых фактов – количество нарушений или положительных деяний (абсолютное число, не переводится в проценты)

#### 9. Автоматическая фильтрация контента
##### Уровень 1 — немедленная блокировка
- Немедленно блокируются (не публикуются) сообщения, содержащие явные призывы:
- К угрозам жизни и здоровью («убью», «зарежу», «взорву», «подожгу»)
- К насильственному свержению конституционного строя
- К государственному перевороту
- К вооружённому мятежу или революции с призывом к немедленным действиям
##### Уровень 2 — сообщения со стоп-словами
- Сообщения, содержащие стоп-слова («революция», «переворот», «насилие», «свержение», «бунт», «восстание»), не публикуются. Автор видит сообщение с пометкой «Заблокировано. Удалите запрещённые слова: [список]».
- Автор может удалить стоп-слова, переформулировать сообщение и отправить повторно. Повторная отправка проходит ту же проверку. Сообщение публикуется только после удаления всех стоп-слов.
##### Стоп-листы
- Списки стоп-слов и фраз для уровня 1 и уровня 2 хранятся в отдельных файлах в репозитории:
- stopwords_level1.txt — явные призывы (немедленная блокировка)
- stopwords_level2.txt — контекстные стоп-слова (требуют удаления автором)
…
- На Этапе 1 все блокировки осуществляются только автоматически. 
- Никакие «доверенные лица», «секретариат» или «модераторы»на первом этапе не имеют права вручную блокировать или разблокировать пользователей. Их нет вообще. 
Никакой человеческой модерации. Только алгоритм.
#### 9.1 Блокировка сообщений и аккаунтов за экстремистские сообщения

- Экстремистские сообщения (призыв к насилию, расправе, госперевороту) не публикуются сами по себе как персональные сообщения. Вместо этого они заносятся в отдельный публичный бланк блокировок: Form №7
- В бланке блокировок указываются:псевдоним автора,текст его сообщения,
дата и время.

#### Техническая реализация:
- При первом запуске приложение генерирует уникальный Device ID и сохраняет его в защищённом хранилище. Способ генерации выбирает разработчик (Android ID, UUID, рекламный ID и т.п.), обеспечивающий уникальность и сохранность между сеансами. Приложение не передаёт Device ID вовне. Device ID привязан к приложению, а не к аккаунту. 
- Приложение хранит список Device ID, с которых уже был подан голос за конкретный проект. При попытке голосования с Device ID, уже присутствующего в списке (даже с другого аккаунта), система блокирует голос и показывает сообщение: «С этого телефона уже голосовали. Один телефон — один голос».
- Новые аккаунты (менее 7 дней) не голосуют
- Защита от «одноразовых» ботов.
- Блокируются только подозрительные голоса, а не проект
Проект продолжает принимать голоса от других пользователей.
#### Раздел 2  Защита приложения и данных
#### 1. Распределённое хранилище (P2P)
- Требование
- Система не должна иметь центрального сервера. Все данные (голоса, оценки, жалобы, предложения, проекты) хранятся в децентрализованной P2P-сети на устройствах участников. Это обеспечивает невозможность блокировки или удаления данных властями.
####   2.	Функциональные требования
Приложение автоматически подключается к P2P-сети при запуске.
Новые голоса, жалобы, предложения распространяются по сети в реальном времени (задержка — секунды, а не часы).
- Должен быть реализован механизм «догоняющей синхронизации» (catch-up sync): если телефон был выключен несколько дней, при включении он должен быстро (за 1–2 минуты) получить все изменения, произошедшие в его отсутствие, и восстановить актуальное состояние.
- Данные не транслируются «всем подряд». Система запрашивает только то, что нужно пользователю в данный момент (по ID, по поиску, по теме).
- Старые жалобы и предложения автоматически удаляются из сети по истечении срока (TTL): жалобы — 1 год, предложения — 2 года, возмущения — 6 месяцев. Итоговые результаты голосований хранятся постоянно.
- Пользователь может отказаться от участия в хранении чужих данных (опция «Только голосовать»), чтобы экономить трафик и память.
- Приложение работает без интернета (голоса сохраняются локально и отправляются при появлении сети).
- После подключения к сети изменения синхронизируются в фоне, без потери данных.
- Пользователь, включивший телефон после двух дней бездействия, видит актуальные рейтинги и жалобы в течение 1–2 минут.
Никакой внешний администратор не может удалить или изменить данные в сети.
#### 3.	Неизменяемость архива (без блокчейна)
- Ежесуточный хеш всех изменений
- Раз в сутки система вычисляет хеш-сумму всех новых записей (голоса, оценки, проекты, жалобы).
- Гарантия целостности обеспечивается публичностью хешей и децентрализованным хранением данных.
- Публикация хеша
Вычисленный хеш публикуется в общедоступном месте (например, в файле hashes.log на GitHub, а также рассылается по P2P-сети).

 абсолютной живучести и безопасности (Air Gap & P2P-Survivability)
Для обеспечения непрерывности управления (Continuity of Power) и защиты от глобальных киберугроз, архитектура НКП (ЭКА) реализует комплексную систему защиты как самого инструмента (приложения), так и смысла (голосования) через независимые децентрализованные протоколы.

#### 1. Протокол физической изоляции (Air Gap)
В основе безопасности данных лежит международный стандарт Air Gap («воздушный зазор»).
- Механизм: Критически важные операции (подписание транзакций, генерация математических ключей, валидация голосования) производятся исключительно на втором (офлайн) устройстве пользователя, не имеющем физического доступа к сети Интернет.
- Результат: Это делает удаленный взлом, подмену данных или вмешательство ИИ технически невозможным, так как «золотая копия» волеизъявления гражданина всегда хранится в изолированной среде.
- 2. Децентрализованная дистрибуция (Anti-Block System)
Система спроектирована как «цифровая гидра», полностью независимая от централизованных корпоративных сервисов (Google Play, App Store) и подверженная принципу «Независимости от магазинов приложений» (App Agnosticism).
- Основной источник кода: Эталонный исходный код и готовые сборки размещаются в открытом репозитории на GitHub. Приложение распространяется в виде автономных установочных пакетов (например, .apk), доступных для прямого скачивания.
- Горизонтальное распространение (P2P Distribution): В функционал приложения встроена возможность передачи своей копии другому пользователю напрямую через Bluetooth, Wi-Fi Direct или локальную Mesh-сеть без обращения к интернету и централизованным маркетам.
- Принцип «Зеркалирования» (Mirroring) и верификация: Любой участник системы имеет право создавать «зеркала» (копии) установочных файлов на независимых ресурсах. Подлинность любой копии (полученной с GitHub, зеркала или от соседа) автоматически проверяется через цифровую подпись автора, которая валидируется офлайн-ключом на втором устройстве пользователя.
- Восстановление через верификацию: В случае массового взлома или порчи кода в централизованных магазинах, система активирует протокол «72 часа верификации». В этот период пользователи полностью переходят на использование резервных P2P-копий приложения, подтверждая свою личность и волеизъявление через офлайн-ключи.
## 3. Опциональное масштабирование через мастер-узлы (Full Nodes)
- Принцип добровольного усиления: Система является полностью децентрализованной P2P-сетью, способной функционировать исключительно на смартфонах пользователей. Однако для повышения скорости синхронизации при пиковых нагрузках (свыше 3–50 млн участников) предусмотрена возможность включения стационарных мастер-узлов.
- Арендованные мощности (VPS/VDS): Любой участник сообщества, волонтерская группа или международная организация имеет право по собственной инициативе арендовать серверные мощности в независимых юрисдикциях для размещения мастер-узла.
## Техническая роль арендованных узлов:
- Ускорение: Выступают в роли высокоскоростных «магистралей» для передачи зашифрованных бланков в периоды пиковой активности (голосования).
- Архивация: Обеспечивают круглосуточную доступность «Таблицы ответов» и истории голосований для новых участников сети.
- Юридический заслон: Размещение узлов на зарубежных арендованных серверах создает международную инфраструктуру, недосягаемую для локального административного давления.
- Децентрализованное финансирование: Система не имеет единого финансового центра. Оплата аренды серверов осуществляется децентрализовано — через целевые гранты международных фондов цифровой свободы или путем краудфандинга (народного сбора).
- Сохранение автономности: Наличие или отсутствие арендованных серверов никак не влияет на логику работы алгоритма Air Gap и TOTP-верификации. Математическая чистота данных проверяется на устройствах граждан независимо от того, через какой узел прошел сигнал.

- Программа считается успешно реализованной и готовой к тестированию только при выполнении следующих измеримых условий:
- AC 5.1.1 Изоляция голосования (Главный критерий безопасности):
- Условие: При входе в приложение под учетной записью «Зарубежный НКП» (верифицированной тремя ПИН-кодами), интерфейс внутренних голосований и референдумов Кыргызской Республики должен быть полностью заблокирован (скрыт или недоступен для клика).
- Проверка: Попытка отправить голос с зарубежного узла во внутренний счетчик КР должна вызывать системную ошибку доступа Error 403: Action Not Allowed.
- AC 5.1.2. Правило «Трех ключей»:
- Условие: Любое официальное действие, отправка заявления, предложения или подписание финансового документа от лица зарубежного НКП требует раздельного ввода 3 независимых ПИН-кодов трех зарегистрированных доверенных лиц.
- Проверка: Если введены только 2 ПИН-кода из 3, транзакция или сообщение не отправляется в сеть и остается в режиме ожидания.
- AC 5.1.3. Автономность и динамический шаблон:
- Условие: Приложение способно запуститься в режиме «Автономный узел» для любой выбранной страны мира.
- Проверка: При выборе, например, Франции или России, интерфейс переключается на соответствующий языковой пакет, а модуль внутренней камеры активирует шаблон распознавания паспортов именно этого государства, не обращаясь к базе данных КР.
- AC 5.1.4. Прозрачность Международной Кассы:
- Условие: В модуле «Единый финансовый центр / Касса» баланс, история поступлений (включая трансграничные переводы) и отчеты о расходах отображаются в реальном времени.
- Проверка: Любой участник сети НКП КР может зайти в аудит кассы и увидеть движение средств. При этом профили управляющих кассой обязаны отображать их реальные ФИО и статус верификации (скрыть личность в этом модуле технически невозможно).

###  Стратегическое значение данной комплектации информационных технологий
- В рамках единой архитектуры НКП (ЭКА) автором проекта была разработана и применена уникальная комплектация трех мощных и независимых ИТ-направлений, формирующих сквозную безопасность системы:
- Сетевой уровень (P2P и мастер-узлы): интегрирован для того, чтобы систему было технически невозможно отключить, подвергнуть цензуре или заблокировать на уровне провайдеров.
- Криптографический уровень (Хеши, «Таблицы ответов» и TOTP): внедрен для обеспечения абсолютной неизменяемости данных, полностью исключая риск подделки, задвоения или подмены голосов.
- Аппаратный уровень (протокол Air Gap): применяется для физической изоляции критических транзакций, что полностью ликвидирует угрозу взлома или скрытого изменения данных на самом устройстве пользователя.
- Таким образом, данное ТЗ представляет собой не просто технический документ, а защищенный цифровой фундамент национального и международного уровня. Это чистокровная авторская комплектация передовых информационных технологий (ИТ), где каждая деталь служит щитом для другой:
- Защита голоса и инструмента: Протокол Air Gap надежно защищает волеизъявление конкретного человека от взлома и слежки, а распределенная P2P-сеть защищает сами данные от удаления и внешних блокировок.
- Устойчивость к нагрузкам и международный иммунитет: Сеть стационарных и арендованных мастер-узлов защищает систему от пиковых перегрузок в моменты голосования и выводит инфраструктуру из-под локального административного давления.
- Защита исторической правды: Синхронизированные математические часы и жесткая структура «Таблицы ответов» фиксируют время отправки бланков, делая чиновников подотчетными в строгих временных рамках.
- Иммунитет к внешнему саботажу: Архитектурная независимость от централизованных корпораций (таких как Google или Apple) гарантирует, что даже полное удаление приложения из официальных магазинов никак не повлияет на бесперебойное автономное существование платформы.
- Международный заслон: Созданная система суверенного сетевого взаимодействия обеспечивает полную защиту внутренних цифровых процессов и кассы взаимопомощи от любого внешнего вмешательства со стороны иностранных государств или ангажированных ИИ-систем.
- Представленный комплекс решений — это чистокровная, авторская комплектация передовых, но разрозненных информационных технологий (ИТ), поставленная автором на службу государственной безопасности, защиты суверенитета и прямого цифрового народовластия. Эти технологии (P2P, Air Gap, хэширование, криптография, мастер узлы) существуют сами по себе давно в разных сферах ИТ, но именно здесь они  соединены вместе.

 #### Раздел 5.2  Технический регламент проверки кода удаления данных (Для разработчиков и аудиторов)
 #### 1. Открытый исходный код (Open Source) и аудит функции очистки.
- Каждый независимый разработчик или международный аудитор имеет право и техническую возможность проверить функцию `shred_and_delete` в исходном коде репозитория. Код, отвечающий за работу внутренней камеры на этапе регистрации, обязан содержать сквозную команду полной перезаписи и уничтожения временных файлов фотографий паспорта и бумажной копии сразу после успешной генерации анонимного Токена гражданства. Если в коде будут обнаружены скрытые функции логирования, дублирования или сетевой отправки исходных изображений, сборка признается скомпрометированной.
...
#### 2. Контроль целостности через Воспроизводимые сборки (Reproducible Builds)
- Чтобы исключить риск подмены честного кода с GitHub на шпионскую версию при публикации в Google Play / App Store или при прямой установке APK-файла, проект НКП/ЭКА обязуется использовать стандарт воспроизводимых сборок. 
- Любой сторонний программист должен иметь возможность скомпилировать приложение из данного открытого исходного кода на своем оборудовании и получить идентичный бинарный файл.

#### 3. Сверка цифрового отпечатка (Хэш-функция SHA-256)
Главным инструментом верификации приложения для конечного пользователя является уникальная буквенно-цифровая контрольная сумма (Хэш):
1. После утверждения стабильной версии кода, системе присваивается официальный хэш-код (например, по стандарту `SHA-256`, который выглядит как строка из цифр и латинских букв, например: `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`).
2. Подобный эталонный номер публикуется на GitHub и в независимых каналах верификации.
3. В самом приложении НКП/ЭКА (в разделе «О программе») должен быть выведен текущий хэш запущенной сборки. 
4. Любой пользователь или доверенный ИТ-специалист может сравнить эти две строчки символов. Посимвольное совпадение хэша на GitHub и хэша в запущенном приложении является математическим доказательством того, что код удаления данных не был изменен, и приложение работает строго по регламенту ТЗ.
