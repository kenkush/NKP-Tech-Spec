#### Раздел 1 Общие требования
Внимание! Весь проект разделён на два этапа. Не все разделы и пункты техзадания всего проекта входят в первый этап. На этом этапе должны решиться только те вопросы, которые указаны в этом техзадании для первого этапа. 
- 1.1.	Система не приводит к автоматической отставке государственных служащих (информационный режим).
- 1.2. Система не требует обращения в ЦОН или иные государственные инстанции.
- 1.3. Код системы публикуется на GitHub (открытая лицензия).
- 1.4. Система не собирает и не хранит паспортные данные, ФИО, адреса проживания, почтовых адресов. Для системы достаточно от каждого заявителя смартфона и второго проверочного телефона без интернета,  на котором будут активированы математические часы.
- 1.5. Система не имеет центрального сервера — вся информация хранится на устройствах пользователей и в распределённых хранилищах (GitHub, Google Диск).
- 1.6	 Система фиксирует момент начала голосования и далее ведёт отсчёт времени локально. При подключении к сети производится корректировка времени по узлам синхронизации. Это внутренний таймер.
- 1.7 Фиксация времени действия: Для каждого голоса сохраняется неизменяемая временная метка момента его регистрации. Временная метка (Timestamp): Для каждого голоса в базе данных будет создана запись, которую невозможно отредактировать задним числом.
- 2.	Регистрация и идентификация пользователя
- 2.1. Первый запуск (анонимный бланк)
При первом запуске приложение генерирует хешированный анонимный бланк — уникальный идентификатор, который не связан с телефоном, email или IP-адресом. Бланк используется только для привязки дальнейших шагов регистрации к одному сеансу.
- 2.2. Фиксация номера телефона (защита от ботов)
Для предотвращения массовой автоматической регистрации система фиксирует два номера телефона заявителя: а) первый_ основной, на котором установлено приложение и б) второй_ проверочный, без интернет связи( кнопочный или сенсорный _ на выбор), на котором будут установлены математические часы.
После фиксации система выдерживает паузу 24 часа (разрыв временной корреляции).
По истечении 24 часов (в любое время в течение следующих 30 дней) при открытии приложения заявителю выдаётся хешированный бланк регистрации.
Если регистрация не начата в течение 30 дней, заявка аннулируется, номер телефона удаляется.
Телефонные номера используются только для защиты от ботов и не связываются с голосованием, псевдонимом или пинкодом.
- 2.3. Генерация секретного ключа TOTP
Приложение НКП на основном телефоне генерирует уникальный секретный ключ по стандарту RFC 6238 (алгоритм SHA-1) для TOTP-аутентификации.
- 2.4. Передача секретного ключа на второй телефон
Секретный ключ передаётся на второй телефон (без доступа к интернету) по защищённому Bluetooth-соединению.
Приложение на втором телефоне (в режиме «Токен») принимает ключ и сохраняет его в зашифрованном виде.
Резервный способ: ручной ввод ключа пользователем (если Bluetooth недоступен).
- 2.5. Второй телефон как TOTP-генератор
Второй телефон обязательно должен быть зарегистрирован на территории КР (косвенное подтверждение гражданства).
Он используется как аппаратный генератор TOTP-кодов (8 цифр, смена каждые 60 секунд).
На втором телефоне установлено то же приложение НКП в режиме «Токен» (без доступа к интернету, только генерация кодов).
- 2.6. Ввод первого и второго кода с часов
Пользователь вводит в приложение на основном телефоне первый 8-значный код с часов (проверка, что часы настроены правильно).
Система ждёт смены кода (60 секунд) и запрашивает второй 8-значный код (новый).
- 2.7. Пинкод для голосования
Второй введённый код становится постоянным пинкодом пользователя — его электронной подписью для всех голосований, оценок, жалоб и предложений.
- 2.8. Присвоение псевдонима
- Пользователь придумывает уникальный псевдоним (обязательно).
- Формат: первая буква — заглавная латиница с точкой (например, G. Gvozdika, J. Jizel). Остальная часть — любой язык (русский, английский).
- Псевдоним не привязывается к реальному имени. Без псевдонима регистрация невозможна.
- 2.9. Бумажная копия пинкода и псевдонима (физическое подтверждение)
- Приложение показывает пинкод (8 цифр), псевдоним на экране, дату регистрации и требует, чтобы пользователь записал их от руки на бумагу. 
Затем приложение собственной камерой фотографирует эту бумагу, загружает  снимок и после сверки цифр,  букв псевдонима и даты снимок удаляется.  
- Без загрузки фото регистрация не завершается.
Фото не передаётся на сервер (сервера нет) и не хранится в приложении. Оно используется только для одноразовой проверки пинкода,  псевдонима и даты регистрации. 
- Бумажная копия (физический листок с пинкодом, псевдонимом и датой регистрации, записанными от руки) остаётся у пользователя и является единственным способом восстановления доступа в систему. 
- 2.10. Хранение пинкода (хеш + соль)
Приложение хранит хеш пинкода + соль (необратимое преобразование). Сам пинкод (8 цифр) не хранится.
При каждом голосовании введённый пинкод хешируется и сравнивается с сохранённым хешем.
- 2.11. Выдача стартовых бланков
После всех шагов система выдаёт 7 бланков (для голосования, жалоб, предложений).
- 2.12. Анонимный режим (по умолчанию)
Псевдоним обязателен, отображается в таблицах голосований.
Права: оценка госслужащих (тайно), выдвижение проектов (анонимно), жалобы.
Рейтинг участника не вычисляется.
- 2.13. Открытый (верифицированный) режим (добровольно)
Пользователь подаёт добровольное заявление и предоставляет: паспорт, ИНН, email, телефон, адрес.
После проверки получает статус «Верифицированный участник», ФИО публикуется в профиле. Псевдоним не используется.
Отдельный пинкод для открытого аккаунта (не связан с анонимным).
Права: открытое выдвижение проектов, открытое обсуждение, открытое голосование (голос привязан к ФИО), а также возможность тайного голосования (с отдельным пинкодом, имя не раскрывается).
- 2.14. Две таблицы результатов голосования
По каждому голосованию система формирует две независимые таблицы:
Анонимные результаты — все голоса, поданные тайно (с псевдонимами).
Открытые результаты — только голоса, поданные открыто (с ФИО верифицированных участников).
- 2.16. Перерегистрация на другой второй телефон
Если пользователь приобрёл другой второй телефон (без интернета), он может выполнить перерегистрацию: вводит коды с нового телефона, второй введённый код становится новым пинкодом, старый пинкод теряет силу.
Пользователь может менять пинкод в любое время через повторную перерегистрацию.
- 2.17. Блокировка иностранных номеров
- 2.18 Телефонные  номера,  не  зарегистрированные  на  территории  Кыргызстана  (по  коду  страны  и  оператору),  блокируются.
#### Регистрация для граждан КР  за руубежом
Для  граждан  КР  за  рубежом  —  отдельная  процедура  регистрации
- 2.19. Регистрация граждан КР за рубежом (через родственников)
- 2.19.1. Кто может приглашать
Только зарегистрированный пользователь в КР, который является кровным родственником приглашаемого: родители, дети, сёстры, братья (по заявлению под личную ответственность). Степень родства не проверяется системой автоматически, но в случае злоупотребления аккаунт приглашающего блокируется.
-  2.19.2. Данные, предоставляемые зарубежным гражданином
- ФИО (как в свидетельстве о рождении).
- Зарубежный телефонный номер.
- Скан/фото свидетельства о рождении (или паспорта гражданина КР, если есть).
#### 2.19.3. Процесс регистрации
Инициация заявки
Родственник в КР подаёт предварительную заявку, указывая ФИО и зарубежный телефон приглашаемого.
Подтверждение «живого» пользователя (код с часов)
Система запрашивает у приглашающего ввести текущий код с его математических часов. После успешного ввода генерируется секретный TOTP-ключ и ссылка-приглашение.
Передача ссылки
Приглашающий отправляет ссылку родственнику за рубежом (мессенджер, email).
Завершение регистрации гражданином за рубежом
Пользователь за рубежом переходит по ссылке, устанавливает приложение и загружает скан/фото свидетельства о рождении (или паспорта КР).
Система проверяет документ автоматически (по шаблону). После проверки оригинал документа удаляется, остаётся только хеш (цифровой отпечаток) и дата верификации.
Затем пользователь настраивает TOTP-генератор (второй телефон), вводит первый и второй код, получает пинкод и псевдоним (по общим правилам).
##### Защита от дублей
Если ФИО + зарубежный номер уже существуют в базе, регистрация блокируется («Этот гражданин уже зарегистрирован»).
- 2.19.4. Ограничения на Этапе 1
Один аккаунт в КР может пригласить не более 10 родственников (лимит может быть изменён НКП).
При аномальной активности (много приглашений за короткое время) заявки временно блокируются до ручной проверки.
- 2.19.5. Ответственность за достоверность
Приглашающий родственник несёт ответственность за то, что приглашённый действительно является гражданином КР. В случае доказанного нарушения (поддельное свидетельство, заведомо ложные данные) его аккаунт блокируется, а право приглашать аннулируется.
      -  2.19.6. Отображение в системеПользователи КР за рубежом отображаются в таблицах с  меткой «КР-зарубежье». Все правила голосования, проектов, жалоб для них не меняются.
#### 2.2 Анонимность голосования
Система не связывает пинкод с конкретным голосом в открытом виде. Даже при физическом доступе к телефону невозможно определить, как проголосовал пользователь.

- 3. Бланки голосования и оценок   
- 3.1. Выдача стартовых бланков (7 штук)
После завершения регистрации пользователь получает 7 виртуальных бланков. Каждый бланк содержит уникальный номер и поле для подписи-пинкода.
- 3.2. Получение дополнительных бланков (без ограничений)
Пользователь может запросить любое количество дополнительных бланков. Система добавляет их мгновенно, бесплатно, без согласования.
- 3.3. Статус использованных бланков (не удаляются)
После использования бланк становится недействительным для нового голосования, но не удаляется. Он сохраняется в архиве как доказательство голосования (уникальный номер, пинкод в виде хеша, временная метка).

Статистической основой для будущего Этапа 2 (когда такие показатели будут закреплены в Конституции).

#### Единое правило подсчёта голосов для всех бланков
- На всех бланках голосования по любому вопросу фиксация ответов происходит по единому правилу:
По каждому пункту голосования гражданин выбирает один из трёх вариантов (например: «Да», «Нет», «Воздержался»).
Каждый участник в соответствующей ячейке (на пересечении строки и столбца) ставит единицу (1) в том варианте, который он выбирает.
- Единица — это числовой маркер, который участвует в математических операциях.
Галочка (✓) не используется, так как она не поддаётся прямому суммированию.
- При подведении итогов система автоматически суммирует все единицы по каждой строке (пункту голосования) и по каждому варианту («Да», «Нет», «Воздержался»).
Доля каждого варианта вычисляется по формуле:
- Доля варианта = (Количество единиц по варианту / Общее количество единиц по строке) × 100%
- Общее количество единиц по строке = сумма голосов «Да» + «Нет» + «Воздержался» по данному пункту.
Результат округляется до одного десятичного знака (например, 45.6%).
Сумма долей по трём вариантам всегда равна 100%.
- Формула универсальна и не зависит от названий вариантов ответа («Да/Нет/Воздержался», «Подтверждаю/Не подтверждаю/Воздержался», «Одобряю/Не одобряю/Воздержался» и т.д.).

#### Раздел 2  Защита приложения и данных
- 1.	 Распределённое хранилище (P2P)
- Требование
Система не должна иметь центрального сервера. Все данные (голоса, оценки, жалобы, предложения, проекты) хранятся в децентрализованной P2P-сети на устройствах участников. Это обеспечивает невозможность блокировки или удаления данных властями.
- 2.	Функциональные требования
- Приложение автоматически подключается к P2P-сети при запуске.
- Новые голоса, жалобы, предложения распространяются по сети в реальном времени (задержка — секунды, а не часы).
- Должен быть реализован механизм «догоняющей синхронизации» (catch-up sync): если телефон был выключен несколько дней, при включении он должен быстро (за 1–2 минуты) получить все изменения, произошедшие в его отсутствие, и восстановить актуальное состояние.
- Данные не транслируются «всем подряд». Система запрашивает только то, что нужно пользователю в данный момент (по ID, по поиску, по теме).
- Старые жалобы и предложения автоматически удаляются из сети по истечении срока (TTL): жалобы — 1 год, предложения — 2 года, возмущения — 6 месяцев. Итоговые результаты голосований хранятся постоянно.
- Пользователь может отказаться от участия в хранении чужих данных (опция «Только голосовать»), чтобы экономить трафик и память.
- Приложение работает без интернета (голоса сохраняются локально и отправляются при появлении сети).
- После подключения к сети изменения синхронизируются в фоне, без потери данных.
- Пользователь, включивший телефон после двух дней бездействия, видит актуальные рейтинги и жалобы в течение 1–2 минут.
Никакой внешний администратор не может удалить или изменить данные в сети.
- 3.	Неизменяемость архива (без блокчейна)
- Ежесуточный хеш всех изменений
- Раз в сутки система вычисляет хеш-сумму всех новых записей (голоса, оценки, проекты, жалобы).
- Гарантия целостности обеспечивается публичностью хешей и децентрализованным хранением данных.
 - Публикация хеша:
Вычисленный хеш публикуется в общедоступном месте (например, в файле hashes.log на GitHub, а также рассылается по P2P-сети).
- 4.  Логирование (неизменяемый журнал событий)
- Система автоматически логирует следующие события:
- Создание, изменение, удаление любого бланка (кто предложил, когда, результат проверки)
- Голосование каждого пользователя (время, пункт, выбранный вариант, анонимный идентификатор)
- Срабатывание автоматической фильтрации (какое сообщение, какое слово/фраза вызвало блокировку, уровень 1 или 2)
- Действия автора по редактированию заблокированного сообщения
- Запуск и остановка системы
- 4.1 Логи невозможно изменить или удалить. Каждая запись содержит неизменяемую временную метку и хеш (цифровую подпись).
- 4.2  Логи хранятся не менее 5 лет.
- 4.3  Логи доступны для просмотра:
Любому гражданину (анонимно) — события, не содержащие персональных данных
Суду, экспертам — полный лог по запросу

#### Раздел 2.1: Стратегия абсолютной живучести и безопасности (Air Gap & P2P-Survivability)
Для обеспечения непрерывности управления (Continuity of Power) и защиты от глобальных киберугроз, архитектура НКП (ЭКА – элдик курултай аянтчалары) реализует два взаимосвязанных протокола:
- 1. Протокол физической изоляции (Air Gap)
В основе безопасности данных лежит международный стандарт Air Gap («воздушный зазор»).
- •	Механизм: Критически важные операции (подписание транзакций, генерация математических ключей, валидация голосования) производятся исключительно на втором устройстве, не имеющем физического доступа к сети Интернет.
- •	Результат: Это делает удаленный взлом, подмену данных или вмешательство ИИ технически невозможным, так как «золотая копия» волеизъявления гражданина хранится в изолированной среде.
- 2. Децентрализованная дистрибуция (Anti-Block System)
- Система спроектирована как «цифровая гидра», независимая от централизованных корпоративных сервисов (Google Play, App Store и облачных серверов).
- •	Независимость от магазинов: В случае взлома, саботажа или блокировки приложения в централизованных маркетах, система переходит в режим автономного распространения.
- •	P2P-передача: Каждое установленное приложение обладает функцией прямой передачи установочного файла (.apk) на другие устройства через Bluetooth, Wi-Fi Direct или Mesh-сети без участия интернета.
- 	Верификация подлинности: Подлинность любой копии приложения, полученной из альтернативных источников (GitHub, зеркала, передача от соседа), автоматически подтверждается через цифровую подпись автора, которая валидируется офлайн-ключом на втором устройстве пользователя.
#### Дополнение к раделу о живучести и безопасности  системы
- Опциональное масштабирование через мастер-узлы (Full Nodes)
- •	Принцип добровольного усиления: Система спроектирована как полностью децентрализованная P2P-сеть, способная функционировать исключительно на мобильных устройствах пользователей. Однако для повышения скорости синхронизации при нагрузках свыше 3–50 млн участников предусмотрена возможность включения в сеть стационарных мастер-узлов.
- •	Арендованные мощности (VPS/VDS): Любой участник сообщества, международная организация или волонтерская группа имеет право по собственной инициативе арендовать серверные мощности в независимых юрисдикциях для размещения на них мастер-узла системы.
- •	Техническая роль арендованных узлов:
- •	Ускорение: Выступают в роли высокоскоростных «магистралей» для передачи зашифрованных бланков в периоды пиковой активности (голосования).
- •	Архивация: Обеспечивают круглосуточную доступность «Таблицы ответов» и истории голосований для новых участников.
•	Юридический заслон: Размещение узлов на зарубежных арендованных серверах создает международную инфраструктуру, недосягаемую для локального административного давления.
- •	Децентрализованное финансирование: Оплата аренды таких серверов осуществляется децентрализовано. Система не имеет единого финансового центра; ресурсы на аренду могут выделяться через целевые гранты международных фондов цифровой свободы или путем краудфандинга (народного сбора).
- •	Сохранение автономности: Наличие или отсутствие арендованных серверов не влияет на логику работы алгоритма Air Gap и TOTP-верификации. Математическая чистота данных проверяется на устройствах граждан независимо от того, через какой узел прошел сигнал.
